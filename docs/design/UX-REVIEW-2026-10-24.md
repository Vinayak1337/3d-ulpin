# Studio UX review, 24 October 2026

The owner asked the lead to find the worst usability problems instead of listing them (24 October). This review
comes from the rehearsal screenshots of 22 to 24 October (REH10 resume, S1.2) and the Studio code. Findings 1 to 12
are about how an officer gets work done; V1 to V8, added on 25 October at the owner's word, are about how it looks.
Each finding has the exact change and the task that carries it.

## The officer's job in five steps

**Add files → we read them → you answer → you confirm → cards.** The Studio shows the parts but never this order.
An officer cannot tell which step a batch is in, what waits on them, or what happens next. Every change below serves
one rule: **at any moment the screen says where you are, what needs you, and gives one button for it.**

## Findings and exact changes

### 1. No "where am I" (worst)

The batch page is one long scroll of panels: the file table, the layout, evidence by key, ready buildings, one
confirmation and history. Nothing says which step the batch is in.

- **Add a step strip** under the batch title: `1 Files · 2 Reading · 3 Your answers · 4 Confirm · 5 Cards`. Each step
  shows a count from the records, for example `3 Your answers (2 waiting)`. The current step is highlighted, and
  clicking a step scrolls to its section.
- **The Batches list gets a Stage column**, plus a `Needs you` count, so the officer sees from the list which batch
  to open.

### 2. No "what do I do now" (worst)

Pending actions are spread across panels; some are disabled and some are missing. In S1.2 the outline said
`Needs an answer` with no button at all.

- **Add a "Needs you" box at the top of the batch page:** one row per pending action, each with one primary button
  that opens it in place. Examples: `Answer the layout of buildings-original.geojson`, `Choose the sheet of
  energy.xlsx`, `Confirm the evidence for key BIN`.
- **When nothing waits,** the box says what the system is doing, with numbers: `Reading 2 files (198 of 211 parts).
  Nothing needs you.`
- **Rule, enforced by a test:** an item in a Needs-you state always has exactly one visible button. The only action is
  never hidden.

### 3. One long page instead of a list and a detail (S7.11)

- **Left: a compact file list.** Each row has a kind icon, name, size, one status chip and one next-step button. Seven
  columns that wrap into narrow strips (Extent showed a column of coordinate digits) become this one row.
- **Right: the selected file's detail pane.** It holds the reading card: what it is, what it holds, its fields with
  a source badge (rule, memory, Sarvam, officer), a small preview, and its question.
- **Below the list: tabs `Files · Buildings · Evidence · History`** instead of stacked panels.
- **A sticky bottom bar:** `Confirm and record: 1,662 buildings from 2 files ready`, enabled only when something is
  ready.

### 4. Status is long prose (S7.5)

- **One chip per file, with a fixed set of five states,** each with an icon and a colour:
  - `Reading` (with a percentage);
  - `Needs you`;
  - `Ready`;
  - `Kept only` (the reason is in the pane);
  - `Stopped` (with Retry).

  The full sentence moves into the detail pane.
- **Hide zero counts.** `0 being prepared · 0 ready to record · 0 needs an answer · 0 held …` becomes only the
  non-zero parts, or one sentence when all are zero.

### 5. Disabled controls without a way out

Examples: `Link a register by a key`, the grey `Record packages…` button, and `Continue` in Add files.

- **Every disabled control gets its reason beside it,** plus a link to the thing that unblocks it. For example:
  `Available once the outline's layout is used. [Answer the layout]`.
- A reason that only repeats the rules (`Only packages with a current review, not being recorded, and…`) is replaced
  by the one condition that fails now.

### 6. Machine words on screen

| On screen now | Change to |
| --- | --- |
| Raw codes such as `(BOUNDARY_CONTACT)` | Plain words, with the code inside a `Details` disclosure |
| `feature 1079580` | The building's name field, its address, or `Building, BIN 1079580` |
| `Revision 0` in the header | Remove it from the header |
| `11,03,282 bytes · Small file` | `1.1 MB` |
| `EPSG:4326` | `WGS 84 latitude/longitude (EPSG:4326)` |
| Extent as raw coordinates | `About 1.2 km × 0.8 km`, with the numbers in Details |
| Card UUIDs first on the verify page | The building name and address first, the ID below |

### 7. The confirmation is a legal wall (S4.9)

- **A summary first:** `You will record 1,662 buildings from 2 files and make 1 card.`
- **Three bullets:** what is recorded, what is not (no rights, no ownership, no ULPIN issuance), and what cannot be
  undone.
- **An editable acknowledgement template,** filled from those facts. Today the box is empty and has no example.
- **The button names the count:** `Record 1,662 buildings`.
- **Afterwards,** a progress view, then a Done panel with three buttons: `Open the card`, `Verify`, `See on the map`.

### 8. Add files has two paths and a blocked Continue (S7.13)

`Blocked: retain the files in the batch, or import each table` stops the officer at the door.

- **One path:** drop → a list of what each file is, with a plain forecast (`Will be on the map in about a minute`,
  `You will choose a sheet`) → name the batch → `Add 4 files`.
- Tables go in like any file (S4.5 now reads certain ones itself). Nothing blocks Continue.

### 9. Batches cannot be told apart

The list shows ten rows named `hdb existing building` and two named `buildings original`.

- **Give each row:** area, number of files, stage, `Needs you` count, and the last change.
- **Suggest a unique batch name** at drop: the first file's name plus the date and time. Warn when a name already
  exists.

### 10. Long work gives no news

- **A dot on the Batches tab** when something needs you.
- **A short toast when a reading finishes or stops,** even after the officer has moved to another page, with
  `Open` on it.
- **Progress shows numbers and a time estimate,** from the records (parts done of planned).

### 11. Batch and map are separate worlds (S7.9)

- From a file or building in a batch: `See on the map`, which centres on its extent.
- From a building on the map: `Open its batch` and `Open its card`.
- The area switcher names the right area (S7.7, running).

### 12. A first-time judge has no start

- **The empty Batches page** gets a three-step `How it works` (Add files → answer → confirm), plus `Try our sample
  files`. The samples are our own NYC kit, labelled test_only.
- **After an answer, focus moves** to the next Needs-you button. Enter does the primary action.

## Visual design

The Studio already uses the design system's tokens (no literal colour in its CSS) and one icon set (Phosphor). The
problem is not the parts but how they are weighted: everything is the same grey, the same size and the same weight, so
nothing leads the eye. The map is the worst case.

### V1. The map scene is washed out (worst)

Measured from the code (packages/scene/src/engine.ts and palette.ts), not guessed:

- Building fill `--ui-map-building` on ground `--ui-map-ground` is **1.2:1**. Building edges on the ground are 1.8:1,
  and edges on the building fill are 1.5:1. Buildings melt into the ground.
- The fog takes the ground colour and starts at 1.4 times the buildings' span, so the far half of a borough fades to
  the same grey as the ground.
- The hemisphere light (1.6) and the sun (1.35) are both white and close in strength, so sunlit and shaded walls come
  out almost equal: the massing reads flat, like the footprints in r09 and r10.
- The realistic look paints a sky gradient, but [map-and-3d.md](../design-system/map-and-3d.md) says "No sky
  gradient".

Exact changes (S7.22):

- Make the sun the key light and the hemisphere the fill (about 2 : 1), with the sun from the south-west at 45° as the
  design system says. Sunlit walls, shaded walls and roofs then read as three distinct greys.
- Draw building edges at least 3:1 against the rendered wall colour. Edges are what make a building read as a
  building.
- Start the fog past the framed area, never inside it. Make the fog a step lighter than the ground, so distance reads
  as haze and not as more ground.
- Use a flat horizon colour in both looks; drop the sky gradient.
- Add a contrast test that renders the NYC fixture and samples pixels. It checks that sunlit wall against ground is at
  least 1.5:1, edge against wall at least 3:1, and that a building at the far edge of the framed area is not fogged.

The test is measured on rendered pixels, not on token values; the tokens stay as the design system sets them.

### V2. A blank map while it loads or draws

The skeleton covers the wait for the area context. After that the canvas is an empty grey field until the first
footprint arrives (r06, REH16 a09).

- The design system already says a map loads with the ground and outlines first. Draw the area's extent as a dashed
  `--ui-map-parcel-line` outline as soon as the context arrives, and frame the camera on it.
- Show the S7.9 floating line on it: `Drawing buildings-original.geojson: 1,240 features so far`.

Carried by S7.9 (the line) and S7.22 (the outline and framing).

### V3. Status in grey prose

- Every file and batch state is shown as one pill chip. It uses `Badge` from packages/ui, with a Phosphor icon, a
  word, and the status colour on its soft fill. `StatusBadge` is not used: its words are the fixed record statuses,
  and these are processing states.
- The five states and their tones:

  | State | Tone |
  | --- | --- |
  | `Reading` | info, with a percentage |
  | `Needs you` | warning (amber means needs review or evidence) |
  | `Ready` | success |
  | `Kept only` | neutral muted |
  | `Stopped` | danger (red means blocking, nothing else) |

- The long sentence moves to the detail pane in `--ui-ink-soft`, never `--ui-muted` for running text.

Carried by S7.5 and S7.11.

### V4. No visual hierarchy on the batch page

- **One `studio-title`:** the batch name. Panel titles are `studio-heading`.
- **The step strip leads the page.** Each step shows its count at `studio-heading` size and its label at
  `studio-label`. The current step has the primary underline, done steps a success tick, and later steps muted.
- **The Needs-you box is the only tinted panel:** `--ui-primary-soft` fill, no shadow (never border, shadow and tint
  together). Every other panel stays on surface.
- **Low-use panels start collapsed** (History, Evidence by key), with their count in the header: `History (14)`.
- **One primary button per view.** Today some panels show two or three primary-looking buttons side by side; the
  rest become secondary.

Carried by S7.17 (strip and box) and S7.23 (titles, collapse, one primary).

### V5. Tables that wrap into strips

Seven columns wrapped into narrow strips; Extent stood as a column of single digits (r01).

- **Rows are 36 px** and cells 13 px, as the density rule says.
- **Names truncate** with an ellipsis and show in full on hover and focus; they never wrap.
- **Numbers are right-aligned** with tabular figures.
- **Sizes are short, in one unit** (`1.1 MB`, decimal, as in finding 6).
- **Extent and CRS leave the table** for the detail pane.
- **At 200 % zoom** the list keeps name, chip and button, and drops the rest into the pane.

Carried by S7.11.

### V6. Monospace used for names

The Add files dialog shows file names in mono (r13). The design system keeps mono for codes, coordinates and
measurements.

- File, batch and building names use Noto Sans.
- Identifiers, hashes and coordinates stay mono. On the verify page the ID sits under the name, at `id-code` size
  (r23).

Carried by S7.13 (dialog) and S7.23 (verify page and the rest).

### V7. Disabled primary buttons look broken

A grey primary with nothing beside it reads as a fault (r20, r21, r13).

- A disabled primary keeps its shape at reduced emphasis.
- Its one reason sits directly under it in `--ui-ink-soft` with the unblocking link (finding 5).
- A view whose only action is disabled shows the reason first and the button second.

Carried by S7.18.

### V8. The layer panel is a page of text

Each layer carries a sentence about its source and state (r09, r10).

- **One row per layer:** kind icon, name, a count (`1,662 buildings`), a visibility toggle, and an `i` button that
  opens the sentence.
- **Layers the area has no data for are hidden.**

Carried by S7.14.

## Order of work

1, 2 and 5 first: they stop a judge getting stuck. Then 3 and 4 (the page shape), then 7, 8 and 9, then 6, 10, 11
and 12. On the visual side, V1 first (the map is what judges look at longest), then V3 and V4 with the batch page
work, and the rest with the tasks that already open those files. Values on every screen come from records only, never samples. Desktop-first and light-only; keyboard,
contrast and 200 % zoom are kept.
