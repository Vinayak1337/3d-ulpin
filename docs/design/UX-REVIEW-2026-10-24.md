# Studio UX review, 24 October 2026

The owner asked the lead to find the worst usability problems instead of listing them (24 October). This review
comes from the rehearsal screenshots of 22 to 24 October (REH10 resume, S1.2) and the Studio code. It is about how an
officer gets work done, not how the map looks. Each finding has the exact change and the task that carries it.

## The officer's job in five steps

**Add files → we read them → you answer → you confirm → cards.** The Studio shows the parts but never this order.
An officer cannot tell which step a batch is in, what waits on them, or what happens next. Every change below serves
one rule: **at any moment the screen says where you are, what needs you, and gives one button for it.**

## Findings and exact changes

### 1. No "where am I" (worst)

The batch page is one long scroll of panels: the file table, the layout, evidence by key, ready buildings, one
confirmation and history. Nothing says which step the batch is in.

- **Add a step strip** under the batch title: `1 Files · 2 Reading · 3 Your answers · 4 Confirm · 5 Cards`. Each step
  shows a count from the records, for example `3 Your answers (2 waiting)`. The current step is highlighted, and
  clicking a step scrolls to its section.
- **The Batches list gets a Stage column**, plus a `Needs you` count, so the officer sees from the list which batch
  to open.

### 2. No "what do I do now" (worst)

Pending actions are spread across panels; some are disabled and some are missing. In S1.2 the outline said
`Needs an answer` with no button at all.

- **Add a "Needs you" box at the top of the batch page:** one row per pending action, each with one primary button
  that opens it in place. Examples: `Answer the layout of buildings-original.geojson`, `Choose the sheet of
  energy.xlsx`, `Confirm the evidence for key BIN`.
- **When nothing waits,** the box says what the system is doing, with numbers: `Reading 2 files (198 of 211 parts).
  Nothing needs you.`
- **Rule, enforced by a test:** an item in a Needs-you state always has exactly one visible button. The only action is
  never hidden.

### 3. One long page instead of a list and a detail (S7.11)

- **Left: a compact file list.** Each row has a kind icon, name, size, one status chip and one next-step button. Seven
  columns that wrap into narrow strips (Extent showed a column of coordinate digits) become this one row.
- **Right: the selected file's detail pane.** It holds the reading card: what it is, what it holds, its fields with
  a source badge (rule, memory, Sarvam, officer), a small preview, and its question.
- **Below the list: tabs `Files · Buildings · Evidence · History`** instead of stacked panels.
- **A sticky bottom bar:** `Confirm and record: 1,662 buildings from 2 files ready`, enabled only when something is
  ready.

### 4. Status is long prose (S7.5)

- **One chip per file, with a fixed set of five states,** each with an icon and a colour:
  - `Reading` (with a percentage);
  - `Needs you`;
  - `Ready`;
  - `Kept only` (the reason is in the pane);
  - `Stopped` (with Retry).

  The full sentence moves into the detail pane.
- **Hide zero counts.** `0 being prepared · 0 ready to record · 0 needs an answer · 0 held …` becomes only the
  non-zero parts, or one sentence when all are zero.

### 5. Disabled controls without a way out

Examples: `Link a register by a key`, the grey `Record packages…` button, and `Continue` in Add files.

- **Every disabled control gets its reason beside it,** plus a link to the thing that unblocks it. For example:
  `Available once the outline's layout is used. [Answer the layout]`.
- A reason that only repeats the rules (`Only packages with a current review, not being recorded, and…`) is replaced
  by the one condition that fails now.

### 6. Machine words on screen

| On screen now | Change to |
| --- | --- |
| Raw codes such as `(BOUNDARY_CONTACT)` | Plain words, with the code inside a `Details` disclosure |
| `feature 1079580` | The building's name field, its address, or `Building, BIN 1079580` |
| `Revision 0` in the header | Remove it from the header |
| `11,03,282 bytes · Small file` | `1.1 MB` |
| `EPSG:4326` | `WGS 84 latitude/longitude (EPSG:4326)` |
| Extent as raw coordinates | `About 1.2 km × 0.8 km`, with the numbers in Details |
| Card UUIDs first on the verify page | The building name and address first, the ID below |

### 7. The confirmation is a legal wall (S4.9)

- **A summary first:** `You will record 1,662 buildings from 2 files and make 1 card.`
- **Three bullets:** what is recorded, what is not (no rights, no ownership, no ULPIN issuance), and what cannot be
  undone.
- **An editable acknowledgement template,** filled from those facts. Today the box is empty and has no example.
- **The button names the count:** `Record 1,662 buildings`.
- **Afterwards,** a progress view, then a Done panel with three buttons: `Open the card`, `Verify`, `See on the map`.

### 8. Add files has two paths and a blocked Continue (S7.13)

`Blocked: retain the files in the batch, or import each table` stops the officer at the door.

- **One path:** drop → a list of what each file is, with a plain forecast (`Will be on the map in about a minute`,
  `You will choose a sheet`) → name the batch → `Add 4 files`.
- Tables go in like any file (S4.5 now reads certain ones itself). Nothing blocks Continue.

### 9. Batches cannot be told apart

The list shows ten rows named `hdb existing building` and two named `buildings original`.

- **Give each row:** area, number of files, stage, `Needs you` count, and the last change.
- **Suggest a unique batch name** at drop: the first file's name plus the date and time. Warn when a name already
  exists.

### 10. Long work gives no news

- **A dot on the Batches tab** when something needs you.
- **A short toast when a reading finishes or stops,** even after the officer has moved to another page, with
  `Open` on it.
- **Progress shows numbers and a time estimate,** from the records (parts done of planned).

### 11. Batch and map are separate worlds (S7.9)

- From a file or building in a batch: `See on the map`, which centres on its extent.
- From a building on the map: `Open its batch` and `Open its card`.
- The area switcher names the right area (S7.7, running).

### 12. A first-time judge has no start

- **The empty Batches page** gets a three-step `How it works` (Add files → answer → confirm), plus `Try our sample
  files`. The samples are our own NYC kit, labelled test_only.
- **After an answer, focus moves** to the next Needs-you button. Enter does the primary action.

## Order of work

1, 2 and 5 first: they stop a judge getting stuck. Then 3 and 4 (the page shape), then 7, 8 and 9, then 6, 10, 11
and 12. Values on every screen come from records only, never samples. Desktop-first and light-only; keyboard,
contrast and 200 % zoom are kept.
