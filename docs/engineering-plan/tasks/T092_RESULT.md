# T092 — imported LiDAR, imagery and elevation map views

Implemented actual binary-source rendering in the shared map. The existing complete Lake View ZIP supplies 62,886 LAS points plus 220 × 230 orthomosaic, DEM and DSM GeoTIFFs. No files were fabricated or replaced for this change; saved packages reopen with the new rendering projection. Canonical geometry, source bytes, identifiers and database records are unchanged.

Map tools → Layers → Map data selects Building model, LiDAR point cloud, Drone imagery, DEM or DSM. The optional comparison overlay shows the separately supplied building model. Source-only mode hides authored city scenery; imagery defaults to plan view, height sources to 3D. Fit uses each source's decoded extent. Elevation colour scale and point/pixel counts are compact; expanded source details give classification, revision and benchmark. Search returns to the building model and focuses the same building/floor identity.

Decoder: explicit asset sidecars bind verified package paths to a named local metre frame. Bounded LAS parsing reads original XYZ/RGB; GeoTIFF.js 3.0.5 reads pixels/elevation, with header/sidecar alignment checks. No-data triangles are omitted. Unsupported frame/CRS, benchmark, dimensions, formats or truncated data produce source diagnostics instead of invented geometry. GPU objects are built lazily, one per active asset and reused; source buffers are owned by the existing scene and disposed with it. The LiDAR view measured one draw call in browser; no broad frame-rate claim.

Validation: 10 tests passed (T092 source parsing/rendering plus T079 complete-package regression); production build including TypeScript passed. Browser uploaded `data-source/lake-view-complete.zip` through the actual file button, opened its draft map, switched all four source types, compared imagery/model alignment, checked source details and DSM at 390 × 667, and returned from DSM through floor-ID search to the register. Screenshots are in docs/evidence/t092/. No test dataset was saved or seeded.

Limits: current synthetic LiDAR contains ground/roof samples, not sensor observations or facade scans. Imagery is a synthetic orthomosaic, not a flight photograph. DEM is genuinely flat at 0 m in this sample; DSM ranges 0–15.5 m. These views do not extract building ownership or floor segmentation. The supported profile is uncompressed LAS, 8-bit RGB GeoTIFF, or single-band north-up pixel-area elevation GeoTIFF in the declared frame. LAZ is retained as an equivalent original, not independently decoded. Larger, rotated, geographic or other projected sources need a reviewed transformation/streamed profile; limits and import schema are documented in docs/LAKE_VIEW_SOURCE_SHOWCASE.md.
