# Implementation is separate from acceptance

T058 and T059 retain their historical results and evidence. Their code is implemented, but remaining defects and visual/device qualification moved into T060 after review of both project chats. The backlog now uses `Implemented` for that condition, instead of keeping multiple historical tasks in active `Review` or inventing user acceptance.

`Implemented` does not mean `Accepted`, does not satisfy an accepted prerequisite, and is excluded from the one-task active implementation limit. T060 and the subsequent T061 local-ML task now have recorded implementation and verification results; neither is marked accepted. Physical-device verification and user visual approval remain explicit qualifications, independent of automated checks.
