## Delivered profile

`services/geo/geo/native_obj.py` inspects UTF-8/ASCII OBJ text (optional BOM), whitespace-delimited polygon records and token-boundary backslash continuations. Ordered `v`, `vt`, `vn`, faces and object/group/smoothing/material declarations retain original literals and zero-based/end-exclusive original-file byte spans, physical line numbers and span hashes. Numeric values accompany their unchanged lexemes; absent components and weights stay absent. Original polygon order and separate coordinate/index streams survive; no triangulation, winding conversion, normals, defaults or measurements are generated.

Face forms `v`, `v/vt`, `v//vn`, `v/vt/vn` require consistent fields within each polygon. Positive absolute indices resolve against the final unchanged file population; negative relative indices use their actual population at the declaration. Original signed indices, resolved zero-based indices and each component's exact byte locator are retained. Zero, malformed/out-of-range indices and nonfinite numeric values refuse the inspection. Unsupported coordinate arities remain indexed source records; affected faces are withheld from eligible projection. Nonunit homogeneous weights remain literal without division/conversion.

Unsupported points/lines, curves/surfaces and vendor directives are inventoried with original statements and a reason. External/executable directives are never evaluated; an unresolved `call` withholds all polygon projection because inserted populations cannot be established. Material library/name declarations return `needs_input`; companion materials/textures are not read or fetched. Object names such as the sample's literal `floor` carry source-native meaning only. Axes, units, CRS, height reference and global placement stay unknown; topology remains unassessed. Outputs are `context_mesh`, with analytical geometry, measurements, property identity, registry admission and learning truth disabled.
