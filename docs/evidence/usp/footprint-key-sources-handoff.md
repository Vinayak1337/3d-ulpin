# SOURCE-KEY-01: two official footprint-key source candidates

The retained [manifest](footprint-key-sources/manifest.json) and [inspection](footprint-key-sources/inspection.json) describe two independent foreign issuer families for sole-learner review. Eleven exact issuer responses, including two five-feature GeoJSON samples, schemas, terms and the IGN guide, are private under `E:/BhuAayam-data/task-data/desktop-source-key-01/`. The byte-pinned private acquisition receipt records 6,154,605 downloaded bytes. No corpus, labels, splits, model or production code changed.

**Dutch BAG Pand.** Kadaster's BAG catalogue defines `identificatie` as a unique object designation; the official OGC schema declares it a string beside polygon geometry. Five native features carry distinct 16-character strings, including leading zeroes. The OGC landing links Public Domain Mark 1.0. The live response is not a frozen release, and its GeoJSON feature UUID is a different identifier. BAG buildings are not Indian property or legal-unit identifiers.

**French IGN BD TOPO Bâtiment.** IGN's July 2026 v3.5 content guide defines `Cleabs` as a required unique 24-character absolute object key applicable to Bâtiment (PDF pages 13 and 20). Five bounded WFS features have distinct string `cleabs` values and MultiPolygon geometry. The guide documents key changes possible on delete/recreate and split/merge, so revisions matter. The issuer's dataset metadata says `lov2`; the linked Licence Ouverte 2.0 allows extraction and adaptation with source/date attribution. The WFS sample includes Z coordinates but no established vertical datum here.

Both are **source evidence candidates**. The learner must independently decide permission eligibility, family/split use and labels before any fit. Five distinct sample keys do not prove global completeness or model performance. No source was called a parcel, ownership record, surveyed interior or Indian operational footprint.

The search began with data.gov.in. Its captured response provided no usable footprint key schema, which is an evidence gap rather than an absence claim. Chicago's issuer metadata has numeric `BLDG_ID`, and Toronto's native records have numeric `OBJECTID`; neither supplied the needed string key. An unbounded IGN WFS request timed out once; the retained five-feature spatial request succeeded. No further source search was performed.

Verification: `scripts/usp/acquire_footprint_key_sources.py --check` validates each retained issuer response against the private receipt; a focused JSON/XML/PDF inspection confirmed wire key types, geometry types, five distinct values per sample, licence declarations and the cited IGN guide pages. Renders of guide pages 13 and 20 were visually inspected. These checks establish source preparation only, not runtime or learning qualification.
