## What the application must predict

The [adaptive ingestion plan](../../orchestration/ADAPTIVE_INGESTION_EXECUTION.md) separates field/operation suggestions from later evidence-backed document-to-building/floor links. [Learning evidence](../../api/learning.md) shows the current E5 field mapper and a retained Qwen3-Reranker-0.6B text-pair checkpoint. Qwen's single local development pass on 25 fields found 7/7 positives and four false mappings on 18 negatives at an uncalibrated threshold; lexical had three false mappings. V6/V7 E5 candidates failed useful calibration, and held-out evaluation remains unopened. No model has demonstrated correct document association, floor identity, Indian-language scan interpretation or forecasting here.

Prediction here is mostly **closed-set judgment** over records already retrieved: choose a known field meaning; flag relevance or contradiction; rank a cited passage against candidate buildings, then candidate floors only under a supported parent; or abstain when the source has no match. It is not a time-series forecast. Unknown, absent, conflicting and no-match must have distinct outputs. Exact identifiers, arithmetic, source integrity, parent constraints, permissions, citations and publication remain deterministic code/record decisions. A well-formed typed answer or a high model score cannot create a missing property fact.

The TypeSafe API is a vendor-hosted service, not an open-weight Jev release. Its SDK/interface alone would not enable local inference. Similarly, JSON schema validity in an OpenAI response is not a calibrated class probability or proof that a cited pixel/region supports the answer. Vision interpretation should follow an immutable page/region crop and retain its source hash, crop geometry and result version; use OCR/layout as the first measurable path for text-bearing scans.

## Smallest useful next decision

Keep deterministic mapping/rules and the frozen Qwen learner experiment as the current path. If a separate prediction comparator is warranted after that result returns, run **one offline GLiClass zero-shot shadow pass** on the already reviewed V8 development/calibration field profiles, using fixed labels including explicit no-match and a pinned checkpoint; compare wrong mappings, positive coverage, abstentions, runtime and memory with the existing lexical/Qwen receipts. Do not tune a threshold on held-out families or treat its publisher F1 as our metric. This is cheap enough to decide whether an open Jev-like label scorer adds value without touching the sole learner, OCR work, corpus or production gateway. For later contradiction checks, mDeBERTa is the more direct candidate once independently cited positive/negative passages exist. For image judgments, first require an actual source-backed scan question and its region-level expected answer; neither the unverified “Decisions API” name nor a visual model's fluent output supplies that evidence.
