# REUSE-02 — small-reranker adaptation recommendation

30 September 2026. **Recommend one bounded LoRA adaptation of the retained Qwen3-Reranker-0.6B, using pointwise yes/no loss after V8 source review. No additional pretrained model download is justified by this research.** This report is a research decision, not a training or quality result. No weights/packages were downloaded, source code executed, model scored, threshold selected or service started.

## What the evidence supports

Accepted V7 Qwen calibration accepts 5/7 positives with zero incorrect accepts at `0.9736446738243103`, but training accepts only 5/11 positives and neither training key. At 0.5 it accepts every positive while making more negative errors than lexical. E5's last-layer fit already used weighted binary cross-entropy on scaled, anchored cosine scores; it failed useful calibration. Consequently, **BCE itself is not a new remedy**. The proposed difference is adapting Qwen's joint field/target representation and native yes/no margin, rather than the E5 cosine geometry. Success remains uncertain with very few independent key families.

Pending V8 adds only four training profiles and one justified key-positive family (IGN). It preserves all 88 earlier inputs; BAG's native key remains unknown. There are only three training key positives if V8 is accepted. Missing descriptions and unsupported lifecycle semantics cannot be repaired by a loss function, translation invented by a model, or repeated rows.

## Techniques worth reusing

| Technique and concrete implementation | Fit to our observed errors | Main limit / required data |
| --- | --- | --- |
| **Pointwise BCE on the final yes/no margin**, with PEFT LoRA. Qwen's [author training guide][qwen-training] links SWIFT; its [Qwen LoRA example][swift-config] uses rank 8/alpha 32 and its [loss code][swift-loss] implements BCEWithLogitsLoss. Sentence Transformers also supplies a [BCE implementation][st-bce] and [training example][st-example]. | Can independently lower non-building polygon/name/key scores and raise supported keys. Explicit negative-only fields participate. Preserve `s = logit_yes - logit_no`, so `sigmoid(s)` equals the original two-token softmax score. | Use source-backed positive/negative labels, not model confidence as truth. Keep the exact retained prompt/tokenization; a generic sequence-classification head initialized at random is not the existing reranker. LoRA capacity cannot establish missing evidence. |
| **Pairwise RankNet; listwise LambdaLoss/ListNet/softmax ranking.** [RankNet code][ranknet] and [LambdaLoss with mined negatives][lambda-example] are concrete maintained examples. | Useful when selecting among many genuinely plausible candidate buildings/floors. Relative preferences can improve candidate order. | A relative ranking loss does not by itself anchor “none relevant.” The inspected SWIFT listwise loss groups one positive followed by negatives and returns zero loss for a batch with no positives. Our geometry fields often have only one type-allowed target. Use no-match supervision in addition to ranking before considering this for association. |
| **Hard-negative mining**, [Sentence Transformers utility][mining]: candidate rank/score windows, absolute/relative margins, optional cross-encoder rescoring, labelled-pair/list outputs. | Later: same site, similar building names, adjacent floors, obsolete revisions and plausible wrong parents provide useful confusing candidates. For present field mapping, all three target combinations are cheap to enumerate; retained USGS/name-like fields already provide real controls. | Mine only within training families and an authorized candidate pool. Scores nominate candidates; independent source review establishes negative labels. Unknown/unlabelled fields are not negatives. Multiple correct records must not become in-batch false negatives. No new mining model is needed now. |
| **Instruction/target conditioning and deterministic type masks.** Both Qwen's guide and SWIFT's [reranker documentation][swift-guide] expose instructions and native target/query text. | Our existing target-as-query design already conditions on meaning. String-only native keys and Polygon/MultiPolygon eligibility prevent coercion and impossible proposals. Preserve these constraints during training and serving. | Type compatibility is necessary but insufficient: counties and buildings both have polygons. Per-target adapters, rewritten prompts or invented descriptions would introduce more variables with too few independent sources. |
| **Embedding InfoNCE with hard negatives**, in the Qwen author guide. | Appropriate later for cheap retrieval over a large candidate registry, followed by a cross-encoder. | Only three schema targets currently exist; retrieval is not the bottleneck. Repeating the same target in a batch makes default in-batch negatives unsafe unless equal-target positives are masked. Retrieval recall and association correctness require separate evaluation. |
| **Abstention / calibration.** [Guo et al.][temperature] study temperature scaling; [Geifman & El-Yaniv][selective] study risk/coverage rejection. | Preserve explicit no-match and ambiguous outcomes; report incorrect accepts and positive recall per target/family. Continue the existing single global threshold policy for a controlled comparison. | A positive global temperature rescales margins monotonically; it cannot improve the achievable zero-error recall by changing score ordering. Four calibration families/seven positives cannot justify per-target calibrators or a population zero-risk claim. Repeated reuse makes calibration development evidence. No conformal/selective risk guarantee is established here. |

### What the published recipes actually demonstrate

The pinned SWIFT Qwen example is **4B on two 20 GiB devices**, all-linear LoRA, BF16/Flash Attention, length 4096, random 2% validation and one epoch on SciDocs. The Qwen author guide also shows full-parameter multi-GPU training. These are concrete implementation recipes, **not RTX 3070 measurements**. Their default prompt differs from our retained prompt, and current SWIFT argument names differ from the older author guide (`tuner_type`/`pointwise_reranker` versus `train_type`/`generative_reranker`). Pin code and adapt the loss/template deliberately; do not paste an unversioned install command.

Sentence Transformers' BCE example expands MS MARCO pairs and then randomly splits them; the inspected Lambda example mines/concatenates examples before its random split and selects by NanoBEIR NDCG. These demonstrate executable training/evaluation patterns, but are not a source-family isolation protocol for us. Split by issuer/layout before expansion/mining; retain our frozen family boundaries and abstention metrics.

The concrete [tomaarsen sequence-classification checkpoint][converted] at `6a5829f5079c66e78d911e06fe21931cc00232f7` explicitly describes a converted copy of Qwen, with usage examples. It is not evidence of a superior supervised adaptation. A deterministic local yes/no-head conversion could later simplify CrossEncoder integration, but requires score equivalence before use and is unnecessary for the next trial. The inspected public search did not establish a community Qwen fine-tune with both reproducible family-separated evaluation and demonstrated advantage on our task; no such improvement is claimed.

## One next experiment, after V8 review

**Hypothesis:** low-rank adaptation of Qwen can improve supported-key acceptance while retaining the current useful zero-error calibration result. Proposed settings below are an engineering choice informed by the recipes, not published optimal settings or an executed freeze.

1. Use the retained revision `e61197ed45024b0ed8a2d74b80b4d909f1255473`; freeze the reviewed V8 corpus, source-only inputs, prior prompt, native target definitions, seed 17 and unchanged type constraints. No downloaded corpus or teacher-labelled property data enters the trial. Preserve every excluded field as unknown.
2. Expand the **44 training fields into 132 field/target pairs**: 14 yes labels, 118 no labels, if V8 is accepted unchanged. One profile per field. Train BCEWithLogitsLoss on the native margin in float32; use training-derived positive weight `min(118/14, 8) = 8`, matching the existing learner's cap. Average over the three pairs per field, then fields per family, then the ten families, so a large schema does not dominate. Do not mine or overweight calibration mistakes.
3. One fixed adapter: LoRA on `q_proj` and `v_proj` across the 28 blocks, rank 8, alpha 32, dropout 0; frozen base/output weights; AdamW learning rate `5e-5`, weight decay `0.01`, gradient clipping 1.0, three epochs. Microbatch one pair, accumulate eight pairs and correctly scale the final partial accumulation; deterministic shuffle and no checkpoint selection on calibration. Use the final adapter only. These settings are fixed before the first gradient step; no sweep follows a disappointing result.
4. Reuse Torch/Transformers and the existing resource supervisor; add a compatible **pinned PEFT** version in an isolated environment when implementing. Borrow the licensed loss/adapter pattern instead of installing the entire distributed SWIFT stack. Preserve left padding, exact suffix/final valid-token handling, FP16 autocast with gradient scaling, SDPA, cache disabled and gradient checkpointing with required input gradients. Freeze exact token lengths and reject truncation; proposed cap 512 accommodates our short profiles only if verified before launch.
5. Score train/calibration once after fitting and save the complete matrices before choosing the one threshold under the unchanged policy. Save/reload the adapter and verify a small deterministic score-equivalence sample. Compare the 65 unchanged profiles to their already saved base-Qwen results; if a full V8 base denominator is wanted, only the four new training profiles need separately identified base scores. Never substitute absent baseline scores. Report fixed-0.5 diagnostics, calibrated per-family/target outcomes and resource peaks.
6. A useful development improvement would recover at least one previously abstained V7 training key while retaining zero incorrect accepts, at least 5/7 calibration positives and positive coverage of every calibration target. Merely memorizing the new IGN key is insufficient. Failure stops this candidate; passing is still not generalization or release qualification. **Halifax/Kitchener and DC/SF remain closed** pending a separately frozen evaluation decision. Do not open them to choose loss, prompt, epoch count or threshold.

## RTX 3070 feasibility and limits

The retained model's actual FP16 weights are about 1.11 GiB; V7 inference peaked at about 1.14 GiB allocated / 1.16 GiB reserved. Those numbers exclude backward activations and optimizer work. From its retained configuration, rank-8 q/v adapters imply approximately **1,146,880 trainable parameters**: `28 × 8 × ((1024+2048) + (1024+1024))`. Adapter/gradient/Adam state is on the order of tens of MiB; activation retention, attention workspace, CUDA context and logits can dominate. Avoid materializing vocabulary logits for every token: last-token-only logits suffice. No measured training-memory result exists.

For that later trial, propose a fresh explicit envelope of **6 GiB GPU allocated/reserved, at least 1.5 GiB sampled free device memory, 6 GiB owned-tree RSS and 600 seconds**, two CPU threads. This is a proposed training envelope, not permission to silently reuse/raise the earlier 3 GiB inference limit. A first optimizer step belongs to the single recorded attempt; if it breaches bounds or gradients are nonfinite, preserve the failure and stop. Do not kill other workloads or change settings and call it the same experiment.

[PEFT's quantization guide][quantization] supports NF4/double quantization plus `prepare_model_for_kbit_training` and LoRA. [Pinned bitsandbytes installation guidance][bnb] includes Windows x86-64 CUDA 12.8/sm86, so QLoRA is possible in principle on this GPU. It adds wheel/CUDA/kernel compatibility, quantization error and reload concerns; activations remain. Prefer plain LoRA for the already small model. QLoRA is a later response to an observed memory failure, not a second automatic candidate. No Linux migration, Flash Attention build, DeepSpeed or quantization dependency is required for the first proposal.

## Later document → building/floor association

Keep a separate model/version and dataset. Retrieve only authorized, revision-correct candidates; apply exact identifier and parent constraints before ranking. Use cited native document spans plus record-backed candidate attributes, independently verified match/no-match/ambiguous labels and whole-site/document-family splits. Include a correct-building/wrong-floor negative only when the source actually establishes floor identity. Measure candidate recall separately from final match precision/coverage. A missing correct candidate must yield no match; competing valid candidates may remain ambiguous. The model proposes evidence links and never establishes ownership, legal identity, floor geometry or access. Private scope checks, stale-revision rejection, provenance, immutable artifacts, bounded execution, reload verification and recoverable failed jobs are current engineering requirements; release-clearance paperwork is a later gate.
