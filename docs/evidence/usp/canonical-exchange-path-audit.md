## Finding

The implemented path ends at **private native inspection** or **legacy prism candidates**. Neither produces an accepted analytical qualification. The exchange endpoint exports identities and a private provenance sidecar, always with empty vertices and an explicit geometry loss. Filling its arrays alone cannot correctly export D1: the canonical registry has no source-native exterior-shell contract, no admission producer and no `qualify_geometry` command. Its review/recording sequence also needs a qualification lifecycle that can admit new geometry without trusting an old revision.

This is code feasibility evidence, not a runtime or real-source gate pass. Existing native-reader/API receipts are reused; LINK-02 owns separate runtime work. The release manifest still identifies GF0 as the next gate.

## Concrete reference, revision and privacy boundaries

1. **Admission is blocked before a new prism can become qualified.** `prepareRegistryReview` checks every geometry-bearing record in the combined draft/current set against `usp_analytic_geometry`, using the same ID/revision and canonical payload. A new reserved draft is revision zero; SQL qualification requires an existing positive current revision. A changed draft payload cannot reuse the old record's qualification. Thus the current sequence cannot first record a new/changed prism and then qualify it. This is a static control-flow finding, not a newly reproduced database failure.

2. **Even an unchanged qualified input does not qualify the recorded result.** `commitRegistryReviewTx` checks READY at the incoming revision, then writes `record.revision + 1`. No qualification is written for that post-state. SQL correctly makes the old annotation ineligible for the new revision. The eventual producer must validate reviewed proposed geometry and atomically bind the accepted receipt/qualification to the actual post-write body and revision; removing FIND/READY guards or copying an old qualification would be incorrect. Source/family/currentness, review and manifest guards must remain effective in that transaction.

3. **Declared reference is not a qualified operation.** `assertFrame` checks an EPSG-shaped ID, nonempty benchmark and metre units. It does not validate axes, vertical datum, source-to-target operation or topology. D1 declares EPSG:7415/NAP; NAP is not an ellipsoidal/ECEF height or Indian placement. Its supplied scale/translate must be decoded exactly once. `validateCityJson` currently requires identity transform and safe-integer vertices, whereas D1's decoded coordinates are fractional. A future exporter needs a versioned lossless coordinate-encoding contract (retained encoded integers + declared transform, or an explicitly supported encoding), not rounding or a blind validator relaxation. It also currently accepts only `Solid` and Building/Storey/Unit; D1 includes BuildingPart and LoD0 MultiSurface, requiring deliberate profile mapping/loss decisions.

4. **Qualification must be consumed explicitly.** `exactInput` collects evidence/right/legacy-geometry source IDs, verifies original bytes, and reads captured records. It neither selects captured qualification pins nor joins their exact target/body/source pins to current export-role eligibility. Historical source readability is useful, but does not establish current analytical eligibility after source supersession, target revision change or retirement. The current empty-geometry loss is honest; future geometry emission must distinguish inspection/history from qualified export and preserve explicit losses on abstention. The private sidecar can already retain unqualified legacy geometry; it is not an analytical pass.

5. **Preserve two hash bases.** Qualification hashes PostgreSQL `body::text` after JSONB normalization. Snapshot/served-projection hashes use application `fingerprint` serialization. Exchange explicitly labels captured versus served hashes after citation omission. These cannot be substituted for the qualification target hash; the writer must compute it on the same PostgreSQL client from the post-state canonical body.

6. **Private serving is present; the native bridge needs its own source authority.** Exchange is private-only and local-operator restricted, uses `no-store`, removes document citations and top-level source object keys, verifies originals, and rechecks document/policy/access authority. Native CityJSON reads additionally enforce their retained subject/access binding, accepted job/fence and artifact hashes via `cityjsonSourceTx` / `CityJSONIngestionService.artifact`. Generic snapshot-original reads call document authority, not that CityJSON authority. A future native representation consumer must carry those checks across the bridge, including after I/O; source existence or a copied artifact key is insufficient. No currently reachable cross-principal CityJSON exchange leak was demonstrated by this audit. Public release/protected multiuser qualification remains separate.

## One smallest dependency-ready implementation slice

**Recommend a bounded, draft-only source-native exterior representation bridge.** Its usable result is: an authorized completed native selection can populate/read a registry **building draft** with a typed physical-representation candidate, exact original/job/artifact/object/geometry pins and explicit unqualified status. It must preserve the native shell representation rather than converting it into an ownership-space prism. This establishes the missing upstream contract and producer without pretending that structural inspection passes admission, topology or analytical qualification.

- Reuse existing registry IDs/drafts/revisions, source storage, jobs and private native artifacts. Add a versioned candidate reference through the existing core asset/representation authority and a typed optional registry field; no second geometry database or duplicated mutable native result. Preserve source object/BuildingPart hierarchy, LoD selection, encoded vertices/transform, ring nesting, semantic indices/nulls and source locators behind immutable hash pins. A reference is a candidate capability, not a qualified solid.
- Admit only server-resolved, bounded, currently authorized accepted native output. Enforce source/case/revision/context/reader/fence/hash pins, expected draft version and request-key idempotency. Link the exterior to the building identity; do not invent floors, units, rights or project codes. If the existing draft requires an XY footprint, use only a traceable supported supplied planar face with an explicit locator/projection record; otherwise return `needs_input`/unsupported rather than flattening a roof or inventing a rectangle. Keep Dutch source coordinates in a separate compatible declared frame/site.
- Restrict this new field to draft candidate inspection until the reviewed canonical-admission/qualification transaction is implemented. Generic recording must explicitly reject this candidate profile; existing prism consumers must not treat an asset reference as measured geometry. Return source applicability, missing reference/topology qualification and recoverable status. Do not enable analytical quantities or geometry export in this slice.
