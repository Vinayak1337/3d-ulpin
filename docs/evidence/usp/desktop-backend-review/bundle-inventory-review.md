## Finding

**P2 — Preserve the encrypted document status for encrypted OOXML ZIPs.** In [`area.py`](../../../../services/geo/geo/area.py), the `flag_bits & 1` branch at line 623 now returns `archive_inventory()` for every request identified as `archive` before choosing the DOCX/XLSX route. The TypeScript reader always sends ZIP bytes as `archive`; the inventory path then returns `format=archive`, `status=unsupported`, `code=ARCHIVE_INVENTORY_INCOMPLETE`, with only a nested member issue `ENCRYPTED`. Before this change, the same encrypted ZIP raised `InputError("Encrypted document archive is unsupported.")`, which [`document-native.ts`](../../../../packages/server/src/modules/usp/ingestion/document-native.ts) maps to top-level `status=encrypted`, `code=DOCUMENT_ENCRYPTED`. A caller using the established status now receives the wrong recovery classification. Preserve the encrypted top-level result for OOXML candidates, or extend the contract deliberately to carry the inventory without losing that status; keep genuinely generic bundle inventory distinct.

Reproduction used an in-memory technical ZIP with `word/document.xml` and the standard encrypted flag set in both local and central headers. A direct extraction of the exact base and candidate `extract_document` functions returned respectively `InputError: Encrypted document archive is unsupported.` and `archive / unsupported / ARCHIVE_INVENTORY_INCOMPLETE / member ENCRYPTED` (exit 0). The TypeScript reader with that returned inventory produced `unsupported / ARCHIVE_INVENTORY_INCOMPLETE`; its prior error path produced `encrypted / DOCUMENT_ENCRYPTED` (both probes exit 0). No source record or service was changed.
