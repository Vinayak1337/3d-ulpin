## Verdict

**Retained observation accepted narrowly; reusable fail-closed harness needs correction.** The saved one-field replay really reports an AppContainer process token with zero capabilities, the native child control prints the same SID and zero capabilities, and the three saved scores match the frozen reload values. This supports isolated-clone behavior for that one observed run. The following two control-flow defects prevent treating the launcher itself as a reliable fail-closed security boundary for another run. They do not establish that the retained run escaped its container.

1. **[P1] Restrict inherited handles.** `appcontainer_audit.py:160-176` allocates room for only one process attribute and sets only `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`; `:181-205` passes the parent's standard input and calls `CreateProcessW(..., bInheritHandles=True, ...)`. Thus every other inheritable handle held by the parent can enter the AppContainer child. A zero-capability token does not revoke an already inherited file, pipe, process, or socket handle. The retained receipts do not inventory parent inheritable handles, so they cannot establish this absence. Use `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` for only the intended output pipe and a deliberately chosen input handle (or launch without inherited handles); add a harmless inherited-handle sentinel control. Do not infer observed egress from this static defect.
2. **[P1] Gate each child on its own token before running it.** `appcontainer_audit.py:211-224` reads the suspended child's token but resumes it without asserting `isAppContainer`, exact expected SID and `capabilityCount == 0`. `:336-342` checks the probe's own token, but its descendant check counts SID strings and does not require two zero-capability reports or a successful child exit. `:361-367` accepts a scoring child on exit code alone; non-Job controls start before token inspection. The retained output independently shows the expected token for the score and two zero-capability native reports, so this is a future fail-open path rather than an observed mislaunch. Centralize validation inside `launch`, before `ResumeThread`, create controls suspended too, and parse/require the descendant's token and exit result.

**Cleanup hardening [P2]:** `appcontainer_audit.py:497-504` logs `icacls /remove:g` and profile-deletion results but never fails on nonzero outcomes; an exception during revocation can skip the remaining revocations and `DeleteAppContainerProfile`. The saved run records exit 0 for all nine replay grants/revocations and profile deletion `0x00000000`; read-only `icacls` on the audit root, venv, model and development directories showed no explicit review SID. Keep cleanup best-effort across every path, always attempt profile deletion, and return a failed audit result if any revocation or deletion fails.
