## 1. What changed in the plans

All 14 original execution documents have been edited directly. The index contains DATA ownership, D0–D7 acquisition runbooks, explicit capability fallbacks, a visual-first sequence and bounded agent concurrency. Shared contracts now specify intake versus snapshots, create/update guards, preparation versus recording, exact manifests, common asset refs, fenced jobs, same-client receipts/outbox and separate derivative release. Every feature names its datasets, expected outcomes, negative cases, actual integration path and copy-paste assignment. The UI file includes the external roof-geometry lane and eight visual/interaction gates in the actual Studio.

These changes adopt the **design instructions**. They do not implement the proposed application modules, download all data, execute browser/DB tests, prove a scanner/model, or qualify real-world rights and survey accuracy. Closure has two dimensions:

* `instruction_status: incorporated` — actionable remedy is in the original execution files.
* `implementation_status: not_verified_in_this_task` — the named implementing owner must produce the prescribed test/artifact evidence. A documentation edit cannot pass a runtime gate.

No new remediation document has been added. This existing audit is shortened to a navigation/history ledger so agents do not have two competing specifications. The immutable original preserves full issue history.

## 3. How an implementing agent closes a row

Work from the relevant original handoff, not historical proposals. Return code SHA, exact dataset/source hashes, schemas/producer-consumer tests, live service receipts and applicable visual/negative-test evidence under the convention in 00. Report contract_ready, local_integrated, real_source_qualified and deployment_qualified separately. Update this ledger only with that evidence; do not replace an unrun check with a confidence assertion.

Full-source catalogue access, licence confirmation, real same-property associations, GPU performance, PDF extraction, live model/client behavior and field survey accuracy remain empirical gates. Each original handoff now gives its bounded attempt and usable fallback. A missing authentic source blocks that claim, not every unrelated implementation task.

## 4. Documentation revision boundary

This remediation edits instructions in the existing folder only. It does not change application code, configuration, database data, source archives or main. The complete historical audit remains accessible at its immutable link above. No claim is made that every possible edge case is eliminated; the specific audited risks now have adopted, locally discoverable implementation rules and tests instead of requiring agents to reconcile an additional proposal document themselves.
