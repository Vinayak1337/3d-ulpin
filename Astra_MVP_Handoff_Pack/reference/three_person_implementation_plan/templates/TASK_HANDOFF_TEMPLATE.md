## Implemented scope

State what actually works and what remains excluded.

## Inputs and expected outputs

Provide fixture/source/request/revision IDs, a valid example, an invalid/error example, the expected result and its independent basis where applicable.

## Run it

Provide environment prerequisites, startup/seed/reset commands, example request/command and automated test command. Never include live secrets.

## Actual evidence

Record command, environment, actual result and relevant request/snapshot IDs. Link logs/screens only for work actually run. State not run for planned checks; distinguish mock, real-service, browser and actual-device evidence.

## Access / provenance / meaning

Record any permissions, source/use restrictions, measurement/reference/quality limits, source ancestry and server-owned state that affect the result.

## Known failures / unsupported input

Provide specific conditions and returned error codes. Do not hide a missing capability behind a successful mock.

## Integration / blocker

Name the real consuming component and whether it has used this output. For a blocker, identify the exact missing artifact, producer and expected behavior.
