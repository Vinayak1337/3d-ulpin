# Project execution rules

This file is a compact template to merge into the actual repository only after respecting existing instructions. The full handoff stays in project documentation; do not inject the entire archive into every worker context.

Build only the first complete manual web/online-native evidence-to-review lifecycle. Preserve the two-client/shared-registry architecture, source/geometry/review distinctions, synthetic local-frame labels and separate reviewer. Vinayak owns the core long-term; A/B own bounded follow-on work.

The parent integrates and freezes contracts. At most three child workers; no recursive spawning. Each child gets one role card, one bounded ticket and a non-overlapping writable path lease. Coding uses explicitly selected Astra; research uses a verified available Luna/Terra/Sol setting suited to the task. Unknown runtime settings must not be claimed.

Do not overwrite user work, edit another lease, add a competing backend, invent government access, upload private sources elsewhere, buy credits/services, weaken tests or expose secrets. No accepted-record seed, fake geometry finding, client-owned acceptance or silent current-record rewrite.

Run focused author tests and independent checks. Preserve actual commands/results/IDs. Mocks, service-only, browser, emulator and actual-phone evidence are different. At a budget/environment stop, leave the last runnable checkpoint, session state and exact remaining task. Never report an unexecuted test passed.

Follow the current work ticket for paths, constraints and required acceptance. Send contract/core changes to the parent; ordinary defects remain the code owner’s responsibility.
